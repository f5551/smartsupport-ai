# ضبط ميزانية إعادة اختبار التذكرة — تحقق محلي

## النتيجة

أصبح حد تكلفة **التوليد النصي** قابلًا للحساب قبل كل طلب باستخدام عدّ الإدخال من الخادم، بدل افتراض تطابق تقدير tiktoken المحلي مع الاستخدام الفعلي. لم يُرسل أي طلب API، بما فيه endpoint العدّ، أثناء هذه المهمة. لم تُنشأ تذكرة دعم عبر MCP أو قاعدة المتجر.

النموذج مقيد بالإصدار `gpt-5.4-mini-2026-03-17` وفئة `default` والعنوان الرسمي العالمي المستخدم في مشغّل الاختبار. حد المهمة يبقى $0.005 واليومي $0.10؛ الإعدادات العامة للوكيل لم تتغير.

## الحد الذي يثبته الحساب

لكل طلب، يقبل الحارس فقط عدد إدخال صحيحًا من الخادم لا يتجاوز 2500، ويحدد الإخراج بحد 96. لا يحسب خصم cache في الحد الأعلى. يُسمح بطلبَي توليد كحد أقصى، وبطلب عدّ واحد لكل طلب توليد، دون retry أو سياق خارجي `conversation`/`previous_response_id`.

```
max_per_generation_usd = (2500 × 0.75 + 96 × 4.50) / 1,000,000
                       = 0.002307
max_two_generations_usd = 2 × 0.002307 = 0.004614
headroom_to_task_cap_usd = 0.005 - 0.004614 = 0.000386
```

التوثيق الرسمي يقرر أن عدّ الخادم هو عدد الإدخال الذي يستقبله النموذج ويشمل بنية الرسائل، وأن حد الإخراج يشمل الرموز غير الظاهرة. الأسعار القياسية المنشورة هي $0.75 للإدخال و$4.50 للإخراج لكل مليون رمز. لذلك هذا حد تعاقدي لحساب التوليد وفق تلك الشروط، وليس قياس API فعليًا جديدًا أو ضمانًا عامًا لفاتورة الحساب والضرائب. لا يثبت التشغيل المحلي توفر endpoint العدّ في الحساب أو قبول الطلب الحي. لم تُتحقق أي رسوم إضافية للحساب محليًا؛ يجب ألا تُضاف رسوم غير مسعرة إلى هذا المسار أو يُقدّم حد التوليد باعتباره إثباتًا لفاتورة كاملة تشملها.

المصادر المفتوحة أثناء الفحص:

- [عدّ الرموز الرسمي](https://developers.openai.com/api/docs/guides/token-counting): يشمل التعليمات والرسائل والأدوات وبنية الطلب؛ `max_output_tokens` يحد الرموز الظاهرة وغير الظاهرة.
- [صفحة النموذج والتسعير](https://developers.openai.com/api/docs/models/gpt-5.4-mini): الإصدار الثابت والأسعار القياسية؛ تشير أيضًا إلى اختلاف تكلفة المعالجة الإقليمية، وهي غير مستخدمة في المشغّل.

## التعديلات

- أضيف `ticket_budget.py`: `BudgetedResponses` يعدّ نسخة من نفس المحتوى الذي سيُرسل، ويضيف `truncation=disabled`، ويرفض المعاملات غير المدعومة والأدوات المستضافة وفئات السعر الأخرى. لا fallback إلى عدّ محلي إذا تعذر العدّ. يثبت إصدار النموذج وحدود الطلب والسعر.
- يحجز الحد الأعلى للطلب في `DailyCostLedger.reserve` ذريًا قبل التوليد. يشمل دفتر اليوم الحجوزات القديمة `unknown`. يسوي usage الحقيقي عند توفره ويحتفظ بالحجز عند timeout أو usage مفقود. أي فشل أو اختلاف عن العقد يغلق الحارس أمام طلب تالٍ.
- عُدل `ticket_retest.py` لتوصيل الحارس مع الغلاف الذي يطلب `create_ticket` أولًا و`none` ثانيًا. الحارس وحده يملك الحجز اليومي لهذا الاختبار، فتعطل الحجوزات التقديرية اليومية المكررة على كائن الوكيل الخاص بالاختبار؛ تظل ميزانية الوكيل وتدقيقه وإحصاءات usage فعالة. لم يتغير منطق الوكيل العام أو أدوات MCP الست.
- الموافقة لا تصدر إذا كان الحارس متوقفًا أو usage مجهولًا. حارس الكتابة السابق يمنع تنفيذ أي كتابة ثانية ويقارن تفاصيل العملية حرفيًا.
