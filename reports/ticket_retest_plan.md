تحديث ضبط الميزانية: أضيف حارس عدّ الإدخال من الخادم قبل كل توليد، مع حد حسابي للتوليد $0.004614. راجع `reports/ticket_budget_verification.md` ونتائج **139 اختبارًا محليًا**. فقرة التقدير المحلي أدناه تصف مرحلة التجهيز السابقة؛ المسار الجديد لا يستخدمها كدليل على عدد الإدخال الفعلي، ويرفض التوليد إذا تعذر عدّ الخادم.

الحالة: تم التجهيز والتحقق بالمحاكاة فقط. لم يُرسل طلب OpenAI، ولم تُنشأ تذكرة SQLite أثناء التجهيز. الموافقات السابقة لا تُستخدم لتنفيذ هذا الاختبار الجديد.

## العملية المعروضة للموافقة

- العميل الاصطناعي: `demo_customer_001`.
- الطلب الاصطناعي: `DEMO-1002`.
- وصف التذكرة الحرفي: «تلف تجريبي لاختبار القبول النهائي».
- تذكرة واحدة جديدة فقط في مجلد مؤقت معزول، وقاعدة موافقات مؤقتة منفصلة. ملفات seed تنشئ سجلاتها الاصطناعية المعتادة؛ يُقارن عدد التذاكر ومعرفاتها قبل العملية وبعدها لتمييز التذكرة الجديدة عنها.
- لا `save_memory`، ولا استعادة أي عملية قديمة، ولا استخدام لقواعد المتجر التشغيلية.

## خطوات التنفيذ بعد الموافقة

1. تشغيل Python خارج العزل الشبكي بإذن التنفيذ المطلوب، باستخدام عميل TLS المركزي والعنوان الرسمي. إعادة قراءة الإعدادات والرصيد الاحترازي يوم التنفيذ.
2. إبقاء SDK دون retries، وإتاحة طلبين API على الأكثر. حد الاختبار جولتان، وإدخال تقديري حتى 2500 رمز وإخراج حتى 96 رمزًا لكل طلب؛ هذه الحدود تخفض الإعدادات للاختبار ولا ترفع إعدادات المشروع.
3. اكتشاف أدوات MCP الست كما يفرض المشروع، ثم إتاحة `create_ticket` فقط للنموذج. يطلب الغلاف الأداة في الجولة الأولى و`tool_choice=none` في الثانية.
4. انتظار `pending_approval`. مقارنة اسم الأداة والطلب والوصف مع التفاصيل المعتمدة أعلاه حرفيًا. إصدار الموافقة من التطبيق فقط عند التطابق ووجود usage مسوّى، ثم استئناف المهمة. يرفض حارس التنفيذ أي أداة أخرى أو محاولة كتابة ثانية، حتى بعد timeout.
5. قبل حذف القاعدة المؤقتة: إثبات وجود تذكرة جديدة واحدة للعميل والطلب والوصف المعتمدين، ومطابقة رقمها مع `write_operations.result_json` في حالة `committed`. التحقق من `final_answer` ووجود الرقم نفسه في الإجابة، ومن الجولات والتكلفة الحقيقية.
6. حفظ تقرير جديد فريد `reports/ticket_retest_<run_id>.json` وJSONL تدقيق `logs/ticket_retest_<run_id>.jsonl`. التقرير العام بقائمة حقول محددة يعرض رقم التذكرة المثبت والنتيجة والرموز والتكلفة والفحوص فقط؛ لا يطبع `AgentResult.as_dict()` أو `write_receipts` أو رمز الموافقة أو الجلسة أو الوصف الداخلي. تحذف قواعد الاختبار المؤقتة بعد التوثيق.
