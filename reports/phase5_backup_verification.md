# استكمال المرحلة الخامسة — نسخ SQLite واستعادتها

**التاريخ:** 2026-11-04
**النطاق:** فحص النسخة المحلية وGit history والنسخ المحلية القريبة، ثم تنفيذ واختبار وحدة نسخ واستعادة. لم تُفتح أي قاعدة تشغيل أصلية أو تُعدّل؛ جميع اختبارات الكتابة استخدمت `tmp_path`. لم تستخدم OpenAI ولم يحدث رفع أو نشر.

## البحث عن النسخة السابقة

لم يظهر `backup_manager.py` أو اختبار backup/restore في شجرة المشروع، ملفات Git المتتبعة، سجل Git المحلي أو النسخ المحلية التي جرى البحث فيها على Desktop. لذلك لم تتوفر نسخة سابقة يمكن استعادتها أو مراجعتها. ملخص README القديم عن عدد الاختبارات لم يذكر تلك الملفات ولا يثبت وجودها. لا نستطيع تحديد هل كانت في مجلد/فرع غير موجود أم لم تُحفظ في checkout.

## التنفيذ الحالي

الملفات المضافة: `backup_manager.py` و`tests/test_backup_manager.py` وهذا التقرير. الملفات المعدلة لهذه المهمة: `web_runtime.py` و`mcp_transport.py` و`mcp_server.py` و`auth_admin.py` لربط قفل التشغيل، و`.gitignore` وREADME و`reports/known_issues.md` و`reports/final_verification.md` للتوثيق. لم تتغير أدوات MCP الست أو منطق Agent.

- `backup_manager.py` يكتشف قواعد SQLite المعروفة: قاعدة المتجر الافتراضية، سجل التكلفة اليومي، قواعد الجلسات وضوابط الويب والحسابات، وقاعدتي المتجر والموافقات في كل مجلد محادثة. مسارات أخرى يمكن تمريرها باستخدام `--database NAME=PATH` عند الإنشاء.
- كل ملف يُنسخ عبر `sqlite3.Connection.backup()`، ثم يخضع المصدر والنسخة إلى `PRAGMA integrity_check`. ينشأ `manifest.json` مع نسخة التنسيق والحجم وبصمة SHA-256 وuser_version ومسار الهدف. يحمي `manifest.sha256` manifest من التلف العرضي. أسماء قواعد المحادثات تستخدم بصمة مختصرة بدل اسم المجلد.
- الاستعادة تتحقق من manifest وبصمات الملفات وسلامة كل قاعدة قبل استبدال أي هدف. تتطلب مجموعة أهداف مطابقة للمجموعة المحفوظة، وترفض اختلاف المسار لتجنب استبدال قاعدة غير مقصودة. تنشئ صور تراجع من قواعد الهدف، وتستبدل ملفًا ملفًا؛ عند فشل لاحق تحاول استرجاع الملفات السابقة. على Windows قد تمنع handles خارجية الاستبدال؛ يفشل المسار بأمان ويعيد الحالة السابقة قدر الإمكان.
- التطبيق وخادم MCP وأداة `auth_admin.py` يحتفظون بقفل تشغيل مشترك. النسخ والاستعادة تتطلب قفلًا حصريًا، ولذلك تفشلان أثناء تشغيل Runtime. ملفات WAL/SHM تمنع الاستعادة أيضًا حتى يتوقف جميع المستخدمين وتُراجع الملفات.
- لا توجد ذرّية جماعية لقواعد المتجر والموافقات والجلسات والتكلفة. كل ملف نسخة صحيحة في لحظته، لكن أوقات النسخ قد تختلف. البصمات تكشف التلف العرضي، ولا تمنع مهاجمًا يستطيع تعديل DB وmanifest وملف بصمته معًا.
- تتضمن النسخة قواعد الحسابات والجلسات والعميل، ومنها تجزئات كلمات المرور ومراجع الجلسات؛ لا يوجد تشفير للنسخ. POSIX يضبط ACL تقليديًا عبر `0700/0600`؛ Windows يرث ACL من مجلد النسخ ويجب على المشغل حمايته. مجلدات النسخ مستبعدة من Git.

تشغيل يدوي بعد إيقاف التطبيق:

```powershell
.\.venv\Scripts\python.exe backup_manager.py --create D:\SmartSupportBackups
.\.venv\Scripts\python.exe backup_manager.py --restore D:\SmartSupportBackups\backup-20261104T120000Z-a1b2c3d4 --confirm-restore
```

استبدل اسم المجلد الافتراضي باسم النسخة الفعلي.

يجب استخدام اسم النسخة الفعلي. الاستعادة عملية استبدال، ولذلك يتطلب CLI الراية `--confirm-restore` صراحة. لا تشغّل هذا الأمر على Render Free وتتوقع دوام `/tmp`.

## الاختبارات

الملف `tests/test_backup_manager.py` يغطي: نسخة متعددة القواعد وmanifest وhash و`integrity_check`، استعادة round-trip، تلف hash، ملف ليس SQLite حتى بعد تحديث بصماته، انقطاع الإنشاء قبل اكتمال manifest، انقطاع الاستعادة بين قاعدتين مع rollback، منع الاستعادة تحت قفل Runtime، تكامل قفل WebBackend، واستمرار idempotency بحيث لا تتكرر التذكرة بعد restore.

- اختبارات النسخ: **10 ناجحة**، بما فيها إنهاء عملية Python فعلية بعد استبدال قاعدة واحدة، ثم التحقق من منع بدء التطبيق وبقاء ملفات التراجع.
- pytest الكامل: **357 ناجحًا، 0 فاشل، واختباران متجاوزان**؛ اختبار OpenAI المدفوع وشرط Linux الحقيقي متجاوزان عمدًا.
- قواعد الإنتاج لم تُستخدم في أي اختبار. لا يختبر هذا التقرير استعادة على Render أو من نسخة متعددة المضيفين.

## الانقطاع وحدود نقطة الاستعادة

قبل استبدال أول قاعدة، يكتب المدير علامة `.restore-pending` بجانب قفل التخزين مع مسارات التراجع ويزامنها إلى القرص. إذا قُتلت العملية، تظل العلامة وملفات التراجع؛ يرفض التطبيق وMCP وأوامر الصيانة البدء حتى يعالج المشغل المجموعة كاملة. عند فشل التراجع تبقى ملفاته بدل حذفها. لا توجد مصالحة تلقائية بعد انهيار restore؛ افحص manifest وملفات التراجع وسلامة جميع الأهداف ثم أعد مجموعة متسقة دون تشغيل الخدمة. لا تحذف العلامة لتجاوز المنع قبل إتمام المراجعة. لا يثبت هذا اختبار انقطاع طاقة أو دوام نظام ملفات شبكي.

تسترجع النسخة البيانات كما كانت عند النسخ. تمنع سجلات idempotency الموجودة فيها تكرار آثارها، لكن العمليات التي حدثت بعد النسخة لا يمكن استعادتها منها: قد تغيب تكاليف حديثة أو إبطالات جلسات أو استهلاك موافقات. يلزم التوفيق مع السجلات الأحدث/الفاتورة قبل إعادة Live أو قبول موافقات تاريخية. لا تدعي الآلية exactly-once خارج نقطة الاستعادة.
- فحص `release_check.py` بعد إضافة التنفيذ: 154 ملفًا نصيًا قابلًا للتوزيع، دون نتائج؛ مجلدات `backups/` و`data/backups/` و`.backup/` مستبعدة من Git، وكذلك قواعد SQLite بامتداداتها.
