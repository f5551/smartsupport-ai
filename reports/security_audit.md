# SmartSupport AI — تدقيق الأمان

تاريخ المراجعة: **2026-11-03**. النطاق: نسخة المشروع المحلية على Windows 11 / Python 3.13.7، مع بيانات اصطناعية وقواعد مؤقتة فقط. لم تُجرَ طلبات OpenAI مدفوعة أو اختبارات ضد أنظمة خارجية، ولم يُعدّل منطق الإنتاج أو بيانات المتجر أو السجلات السابقة.

## الخلاصة

**الضوابط المحلية لهوية جلسة MCP والموافقات تعمل في الحالات المختبرة، لكن المنتج غير صالح حاليًا لبيانات عملاء حقيقية.** لا توجد مصادقة إنتاجية، وتوجد فجوة ذرّية بين استهلاك الموافقة وكتابة المتجر، ويمكن استنفاد سجل الزوار طوال عمر العملية. اختبارات Fake تثبت أن حدود الأداة لا تعتمد على طاعة النموذج، لكنها لا تثبت مقاومة النموذج الحقيقي للحقن أو دقة إجاباته.

لم تُثبت ثغرة Critical في هذا النطاق؛ هذه ليست شهادة خلو من الثغرات. مراجعة الاعتماديات الخارجية المضافة أثناء استكمال التدقيق موثقة أدناه، ولا يغني عنها نجاح `pip check`.

## الأدلة القابلة لإعادة الفحص

- [حزمة الفحص المحلية](evidence/security_probe.py)، [نتائجها JSON](evidence/security_probe_results.json): **7 تأكيدات فحص ناجحة، 0 فاشلة**. منها **4 معايير حماية ناجحة و 3 معايير إنتاج فاشلة**. نجاح التأكيد الذي يعيد إنتاج عيب لا يجعل معيار المنتج ناجحًا.
- [نتائج pytest بصيغة JUnit](evidence/security_pytest.xml): **80 passed، 0 failed، 0 skipped** في **73.20 ثانية**. تشمل مجموعات `test_phase5_security.py` و`test_approval_store.py` و`test_mcp_integration.py` و`test_database.py` و`test_audit_logger.py`.
- [فحص القالب وملفات الإصدار](evidence/security_static_checks.json): مفتاح `.env.example` فارغ، ولا نتائج في فحص أنماط أسرار الملفات القابلة للتوزيع. لا يوجد مستودع Git محلي يمكن تدقيق ملفاته المتتبعة أو تاريخه.

الأعداد أعلاه مجموعات فرعية متداخلة مع المجموعة الكاملة في تقرير الجاهزية؛ **لا تُضاف أعدادها إلى العدد الكلي للمشروع**.

## حدود الثقة المثبتة

- النموذج لا يحدد `customer_id` أو `session_id` أو `approved` أو `approval_id` في مخططات Responses. جلسة MCP تُثبّت الهوية من معاملات إطلاق موثوقة محليًا، وليست هوية مستنتجة من رسالة العميل.
- استعلامات التطبيق تستخدم معاملات SQL مرتبطة وشروط عميل/جلسة. إنشاء التذكرة يربط ملكية الطلب في عبارة INSERT-SELECT واحدة، ومفتاح أجنبي مركب يمنع تناقض ملكية التذكرة والطلب. هذه ليست Row Level Security إذا مُنح طرف غير موثوق وصولًا مباشرًا إلى ملف SQLite.
- الإصدار الحالي يعامل الموافقة كقدرة عشوائية مربوطة بالعملية والمدة والهوية، ويستهلكها مرة واحدة خارج سلطة النموذج. النسخة العامة تمنع Live في الخادم؛ ليست دعوة لعرض Live على شبكة عامة دون مصادقة.
- سجل التدقيق يضع حقولًا مسموحة ويستخدم pseudonym مستقلًا للجلسة. نجاح `fsync` ليس سجلًا غير قابل للتلاعب أو سلسلة إثبات سلامة؛ حساب النظام المحلي يبقى داخل حد الثقة.

## الأسرار وحدود التحقق

لم نعرض أو ننسخ أي مفتاح حقيقي، ولم نحمّل `.env` بغرض الطباعة. `.env.example` فارغ المفتاح ومسح التوزيع لم يجد نمط سر. لا يعني ذلك أن كل سجل تاريخي أو ملف ثنائي أو حساب خارجي نظيف، ولا يثبت تدوير المفتاح المنكشف سابقًا. لا يوجد Git repository في النسخة الحالية، لذلك حالة الملفات المتتبعة وتاريخ Git **غير متحققة**. لا توجد هنا نتائج لاختبار اختراق خارجي أو لجودة مقاومة OpenAI نفسه للحقن.

## شروط القبول الأمني قبل الإطلاق

تُغلق SEC-H01 إلى SEC-H04 بأدلة تنفيذ واختبار؛ يوثق تخزين دائم وسياسة بيانات، وتُعالج حصص العملاء وتنظيف الموارد؛ تُنفذ الحالات العشر المختارة للـ OpenAI بعد تفويض جديد مع قواعد حكم موضوعية. حتى ذلك الحين تبقى النسخة **Demo ببيانات اصطناعية فقط**، ولا يُعتبر مرور الاختبارات الحالية قبولًا أمنيًا للإنتاج.

## مراجعة الاعتماديات المعروفة

أُرسل جرد أسماء وإصدارات **61 حزمة PyPI** فقط إلى OSV العام، دون مفاتيح أو بيانات متجر. راجع [الجرد](evidence/installed_packages.json)، [أداة الاستعلام](evidence/dependency_audit.py)، [ردود النشرات](evidence/dependency_audit.json)، و[الملخص بعد دمج aliases](evidence/dependency_summary.json). اكتمل الاستعلام بلا أخطاء. ليست `pip check` أداة ثغرات؛ نجحت لفحص توافق المتطلبات فقط.

النتيجة **18 مطابقة نشرة =11 ثغرة فريدة** بعد دمج CVE/GHSA/PYSEC:5 في `mcp==1.27.2` و 6 في أداة البناء `pip==25.2`. حسب تصنيف `database_specific.severity` المتاح في النشرات: **0Critical، 1High، 9Moderate، 1Low**. تحفظ الأدلة متجهات CVSS الأصلية أيضًا؛ لا نحول تضارب المتجه/التصنيف إلى شهادة أمان. لا تشمل هذه النتيجة جميع أخطار نظام التشغيل أو ثغرات غير معلنة.

## تحقق المتصفح المكمّل وسلامة أدلة التقرير

شُغّلت نسخة Public Demo على loopback وبقاعدة `reports/evidence/ui_fixture` فقط. في Chrome، عُرضت حمولة مستخدم `<img ... onerror=...>` كنص حرفي؛ صفر عناصر الصورة المحقونة وغياب علامة التنفيذ. فحص مخرجات النموذج الخبيثة عبر AppTest موثق في SEC-P06؛ لا ندّعي اختبار نموذج حي. راجع [DOM](evidence/ui_xss_ax.txt) و[نتائج المتصفح](evidence/ui_browser_results.json).

فحص أسرار نهائي وجد نمط مفتاح اصطناعي في اسم حالة parametrized داخل JUnit الذي أنشأه هذا التدقيق، **وليس المفتاح المحلي الحقيقي**. نُقّح هذا الوسم في ملف الدليل الجديد فقط، دون تغيير أعداد/نتائج الاختبارات أو أي سجل أصلي؛ راجع [إثبات التنقيح](evidence/artifact_redaction.json). أصبح فحص الملفات القابلة للتوزيع بلا نتائج بعد التنقيح. لا يصح تضمين مخرجات اختبار ذات شكل أسرار آليًا دون تنقيح.
