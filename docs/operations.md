## تشغيل MCP وAgent دون API مدفوع

من جذر المشروع بعد تثبيت الاعتماديات:

```powershell
.\.venv\Scripts\python.exe mcp_client_test.py
.\.venv\Scripts\python.exe agent_cli.py --fake-demo
```

عميل الاختبار و`--fake-demo` يستخدمان SQLite مؤقتة وMCP فعليًا. الخادم stdio لا يفتح منفذ شبكة؛ stdout مخصص لـJSON-RPC، والتشخيصات إلى stderr. اكتشاف الأدوات لا يمنح صلاحية الكتابة. لا تشغّل `--live` أو `RUN_LIVE_OPENAI=1` دون تفويض منفصل للتكلفة والكتابة المطلوبة.

## الجلسات والهوية

واجهة العرض الحالية تفتح مباشرة؛ العميل ثابت `demo_customer_001` وهوية الجلسة عشوائية. أدوات MCP لا تقبل الهوية كمعامل يختاره النموذج. جلسة أخرى لا تسترجع ذاكرة الجلسة الأولى. هذه حدود Demo محلي/عام اصطناعي، وليست إثبات هوية عميل إنتاجي. أدوات إدارة الحسابات القديمة ليست مسار الدخول الحالي.

خمول الزائر افتراضيًا 1800 ثانية؛ يمكن ضبط `SMARTSUPPORT_VISITOR_IDLE_SECONDS` في بيئة الخادم قبل بدء التشغيل. التنظيف يلغي تسجيل الزائر المنتهي، ويحمي العملية النشطة ولا يحذف المحادثات أو الأدلة. استعادة سياق SQLite لا تعني صلاحية استعادة جلسة منتهية؛ إذا تعذر إثبات الهوية يبدأ المستخدم جلسة جديدة. لا يُعاد تنفيذ OpenAI أو كتابة MCP تلقائيًا بعد إعادة التشغيل.

## موافقات الكتابة والتكلفة

سياسة `ask_on_write` تشمل `create_ticket` و`save_memory`. الموافقة محددة للعملية والهوية والمحتوى والزمن؛ التغيير يحتاج موافقة جديدة. إعادة الطلب ذي الهوية نفسها تستخدم نتيجة الكتابة المحفوظة والمصالحة، ولا تنشئ أثرًا جديدًا لمجرد انقطاع الاتصال. عند غموض النتيجة لا يجوز ادعاء النجاح أو تكرار الكتابة دون فحص السجل.

التكاليف المسوّاة غير الحجوزات. `DAILY_COST_DB_PATH` يحدد دفتر التكلفة عند إعداد المسار الحي؛ لا تستخدم قيمة بيئية شكلية لإيهام وجود قرص دائم. القفل والحساب اليومي على مضيف واحد لا يمثلان عدادًا موزعًا. الحجز التاريخي unknown بقيمة $0.002445 محفوظ دون تحرير أو إعادة تصنيفه. [تحليل التكلفة](../cost_analysis.md).

## النسخ والاستعادة

[backup_manager.py](../backup_manager.py) يكتشف قواعد المتجر والموافقات والجلسات والضوابط والحسابات والتكلفة الموجودة؛ تشمل النسخة SQLite Backup API وmanifest وSHA-256 و`PRAGMA integrity_check`. أوقف Streamlit وعمال MCP قبل الصيانة؛ القفل الحصري يمنع الاستعادة أثناء التشغيل.

```powershell
.\.venv\Scripts\python.exe backup_manager.py --create D:\SmartSupportBackups
.\.venv\Scripts\python.exe backup_manager.py --restore D:\SmartSupportBackups\BACKUP_SET --confirm-restore
```

استبدل `BACKUP_SET` بالمجلد الناتج؛ يمكن إضافة قاعدة مخصصة بـ`--database NAME=PATH`، وتخصيص مساحة الويب بـ`--web-data-dir PATH`. لا تستخدم النسخ كملفات تسليم عامة: قد تتضمن بيانات جلسات وحسابات مجزأة، ولا يوجد تشفير للمحتوى. على Windows تحكمها ACL للمجلد الأب؛ وعلى POSIX يطبق قيد الصلاحيات. النسخ متسقة لكل قاعدة، **وليست ذرية كمجموعة**. checksum يكشف التلف ولا يثبت المصدر ضد مهاجم يعدّل manifest والنسخة معًا. [دليل الاختبارات التاريخي](../reports/phase5_backup_verification.md).

## TLS وسلامة الإصدار

[openai_transport.py](../openai_transport.py) يستخدم SSLContext موحدًا: Windows trusted roots على Windows وcertifi خارجه، مع `CERT_REQUIRED` و`check_hostname=True`. لا تستخدم `verify=False` أو تعطيل الحماية لتشغيل العرض. Demo لا يحتاج اتصال OpenAI.

فاحص [release_check.py](../release_check.py) يفحص الملفات القابلة للتوزيع وأنماط الأسرار ونص PDF المستخرج، ويفشل إن تعذّر استخراج PDF؛ `pypdf==7.0.0` مثبت صراحة في CI. الفحص ليس ضمانًا لغياب كل الأسرار ولا OCR. تبقى `.env` وقواعد التشغيل والنسخ الاحتياطية و`.venv` و`.git` والسجلات الخاصة خارج التسليم وفق [.gitignore](../.gitignore). لا تعِد توليد traces التاريخية لتحديث نتائجها.
