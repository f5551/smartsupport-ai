# العرض العام على Fly.io

[الرئيسية](../README.md) · [العرض التجريبي](https://smartsupport-ai.fly.dev/)

## ما ثبت وما لم يثبت

رابط العرض مقدم من صاحب المشروع. جُلبت ملفات النشر من `origin/main` عند Commit `2d194b7295052f99e35aedd857660bd29583016e` دون تعديلها: [Dockerfile](../Dockerfile) يستخدم Python 3.12.16 ويبدأ Streamlit على 8501؛ [fly.toml](../fly.toml) يطابقه بمنفذ داخلي 8501 وذاكرة 1GB ومنطقة ams وHTTPS مفروض وتشغيل/توقف تلقائيين. لا توجد Volume أو قيم Demo ضمن الملف. لم تُقرأ Secrets أو حالة إعداد Fly البعيدة ولم يُنفذ نشر. القيم أدناه عقد تشغيل مستخرج من [runtime_policy.py](../runtime_policy.py) و[WebBackend](../web_runtime.py)، وليست شهادة بأن الخادم البعيد مضبوط عليها الآن. إصدار Python في صورة Fly يختلف عن 3.13.7 المستخدم في CI؛ نجاح CI لا يثبت اختبار الصورة نفسها.

فحص الروابط في 2026-11-07 أعاد HTTP 200 لصفحة العرض عبر HTTPS، دون مفتاح API. هذا فحص وصول للصفحة فقط، وليس اختبارًا لتفاعلات الواجهة أو إثباتًا لقيم البيئة البعيدة.

## متغيرات البيئة

ضعها في إعداد بيئة التطبيق أو Fly Secrets؛ هذه القيم ليست أسرارًا:

```env
SMARTSUPPORT_PUBLIC_DEMO_ONLY=1
SMARTSUPPORT_DEPLOYMENT=public
SMARTSUPPORT_ENABLE_LOCAL_LIVE=0
RUN_LIVE_OPENAI=0
SMARTSUPPORT_WEB_DATA_DIR=/tmp/smartsupport-ai
SMARTSUPPORT_MAX_WORKERS=2
PYTHONIOENCODING=utf-8
```

- `SMARTSUPPORT_PUBLIC_DEMO_ONLY=1` يتيح الدخول المباشر من عنوان عام ويمنع عامل Live حتى لو وُجد مفتاح OpenAI. لا يكفي `RUN_LIVE_OPENAI=0` وحده؛ فهو يخص opt-in لاختبار pytest المدفوع.
- `SMARTSUPPORT_DEPLOYMENT=public` و`SMARTSUPPORT_ENABLE_LOCAL_LIVE=0` يغلقان إعدادات Live المحلي. لا تضبط `RENDER=true` للتحايل على اكتشاف المنصة؛ استخدم متغير Demo الصريح.
- لا يحتاج Demo إلى `OPENAI_API_KEY` أو `OPENAI_MODEL`؛ لا تضف مفاتيح حقيقية للصورة أو المستودع. النموذج محاكى؛ الأدوات وقواعد SQLite حقيقية لكن بياناتها اصطناعية.
- `SMARTSUPPORT_WEB_DATA_DIR` مسار مخصص للعرض فقط. لا توجهه إلى قاعدة متجر أو نسخة احتياطية حقيقية.
- لا تغير سياسة `ask_on_write` أو حدود التكلفة. إنشاء التذكرة وحفظ الذاكرة يظلان خلف موافقة المستخدم على التفاصيل.

رسالة «الدخول المباشر متاح فقط…» تظهر إذا لم يُفعّل القفل العام وكان الربط غير loopback؛ Fly لا يفعّل متغير Render التلقائي. القيمة `SMARTSUPPORT_PUBLIC_DEMO_ONLY=0` في قالب `.env.example` لا تفعّل العرض العام.

## عقد تشغيل الخدمة

بعد تثبيت [requirements.txt](../requirements.txt)، شغّل Streamlit من جذر التطبيق:

```sh
python -m streamlit run app.py --server.address 0.0.0.0 --server.port 8501 --server.headless true
```

الأمر يطابق `internal_port=8501` في ملف Fly وCMD في Dockerfile المحفوظين؛ لم تُتحقق حالة Machine البعيدة. لا تنسخ إعداد bind المحلي `127.0.0.1` لخدمة عامة. نقطة فحص الصحة `/_stcore/health`؛ نجاح HTTP لا يكفي وحده لإثبات المحادثة أو الموافقات، ويلزم فحص UI بعد أي نشر يصرح به صاحب المشروع. تبقى CORS وXSRF وTLS وحواجز Live مفعلة؛ لا تُحل مشكلة الإعداد بتعطيلها.

## SQLite والتخزين

حفظ الذاكرة واسترجاعها بعد إغلاق عملية MCP وتشغيل أخرى يعمل إذا بقي الملف نفسه. التخزين في `/tmp` أو جذر Machine المؤقت لا يضمن البقاء بعد استبدالها، ولا تشارك نسخ مستقلة من Machines ملفات SQLite تلقائيًا.

إذا لزم حفظ طويل الأمد، يجب إعداد Volume دائم ومسار موثوق مخصص للبيانات الاصطناعية، مع نسخ احتياطي وقفل صيانة. لم تُنشأ Volume هنا ولا يُدّعى وجودها. قواعد المتجر والموافقات والجلسات والتكلفة منفصلة، ولا توجد معاملة ذرية تجمعها. [التشغيل والنسخ الاحتياطي](operations.md).

## حدود التسليم

التعليمات الأصلية المتاحة ذكرت **Render أو Railway**. Fly.io عرض متاح من صاحب المشروع، وليس منصة ثبت اعتمادها رسميًا للكابستون. اطلب قبول المقيم أو استوفِ المنصة المطلوبة. بقي [render.yaml](../render.yaml) دون تعديل بصفته خيارًا آخر؛ التقارير التي تصف غياب Render هي أدلة تاريخية لا تنفي وجود رابط Fly المقدم لاحقًا.

## ملاحظة أمان لصورة البناء

ملف [.dockerignore](../.dockerignore) القادم من البعيد يستبعد `.git` و`.venv` والكاش و`.envrc`، لكنه لا يستبعد `.env` أو SQLite أو النسخ المحلية. `.gitignore` يحمي قائمة Git وليس سياق Docker، وDockerfile يستخدم `COPY . .`. لا تبنِ من مساحة عمل تحتوي ملفات خاصة؛ استخدم نسخة نظيفة من الملفات المراجعة، أو راجع استبعادات Docker بمهمة منفصلة قبل أي نشر. لم تُعدّل ملفات النشر هنا.
